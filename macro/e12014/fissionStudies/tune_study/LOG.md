# Fit Tuning Study: Log

Dated record of the study's decisions and events, newest last. "User" marks the user's decisions. The report is [README.md](README.md); this file is not maintained as a summary.

## 2026-10-18

- **Scope (user).** All three knob groups. Fit-model fidelity first, iterations × rounds second, search shape (prior scale, degrees of freedom, narrowing) only if iterations × rounds get strange.
- **Goal (user).** Map capabilities; no pass/fail against 100 × 2 and no reference fit. Everything is measured against the simulated truth.
- **Pseudo-data (user: finer than any fit, made once).** Chose 0.25 mm and 4000 points (2× finer step than the finest fit tried, 4× the default points; 6 CPU-s/event digi).
- **Flat Z through `sim.zToSimMax`.** One data set instead of several fixed-split sims, which would each need their own fit sections (a fit's input files must share their sim settings). Range 43–54 (light 42–31). Rejected events are redrawn, so it is flat before acceptance.
- **3000 events, `fit.threads = 4`, `fit.saveEvents = 0`.** Production thread count; nothing reads saved events.
- **Core cap (user: about half the physical cores, 2/3 at most).** 128 cores. First plan pinned jobs to two nodes; the user rejected forcing the scheduler's node choice. Jobs are submitted held and `throttle.sh` (login node) releases them oldest first under 128 cores of my jobs, only once their dependencies are met.
- **Phase A grid.** Steps 0.5–6 mm; random and fixed-pattern points 300–10; 2σ longitudinal window; gain fluctuation off. `base2` is `base` reseeded, the floor of the paired columns.
- **Autonomy (user).** No consultation between phases; decisions recorded here; report kept pushed to `origin/fit-tune`.
- **Report location (user).** Study-local (`tune_study/`), not `docs/`.
- **Angle confound (user).** The fit fails away from 90°, which would swamp every knob. Confirmed on the sampled-angle `base`. Cancelled 900 Phase A jobs (8 had just started), kept `base`, let `base2` finish, made `tune_data90.ini` (`sim.decayAngle = 90`) and resubmitted Phase A as `tune_fid90.ini`. `tune_fid.ini` keeps `base`, `base2` and the E2 sections.
- **Bias first (user).** Bias is the lead metric.
- **Extensions (user suggestion).** E1/E2 decay angle (does more search help off 90°?), E3 energy-loss pairing.
- **Rule for a "free" setting, v1 → v2.** v1 tested 12 Z bins at 2σ each with unpaired errors and |dZ| rather than bias; a free setting would fail one bin by chance about 40% of the time. v2: paired, signed bias, one chi2 over the Z bins.
- **Unfolded dZ.** The folded dZ (lighter of the true pair vs lighter of the fitted pair) has a cut-off: the fitted light Z cannot exceed 42, so near-symmetric splits err one way only, and swaps count as perfect. Built fragment matching by azimuth (`sim_truth.C`, `dump_fit.C`'s `ph0`/`ph1`). Validated: of 136 clearly right asymmetric events, 127 match to the true Z; 8 of the other 9 are unambiguous swaps at θCM ≈ 20° or 150°, 1 is ambiguous. Adopted as the primary measure.
- **Budget, Phase B, E2.** About 8 h of 128 cores overnight. Phase A on all 3000 events (about 4.2 h); Phase B and E2 on the first 30 chunks (1500 events), each with its own paired base. 400 × 3 dropped for cost.
- **Submission chain.** `chain.sh` (local) waited for the 90° data with ssh failures retried, then submitted Phase A, Phase B and E2 in priority order; all three submitted at 21:01 (1020, 420 and 90 jobs).
- **`--no-sync-check`.** The cluster checkout stays at the study-code commit; later commits are reports and analysis tools, which the jobs don't run.
- **E3 setup.** On 90° events. `tune_data90_srim.ini`: SRIM fragment tables, same seeds; the beam keeps LISE through the new `sim.beamEloss` (no SRIM beam table on the cluster). `tune_eloss90.ini`: each data set fit with each table, 1500 events. Runs from a second checkout (`hpc-tune2`, same data directory), since `--sync` refuses while a checkout has queued jobs.
- **No event selection; rule v3 (user question: why cuts?).** The cuts were inherited from the speed study's gate. They select on the fit's own outputs, so a worse configuration could be measured on a cleaner subset. Now every fitted event counts; core (|dZ| ≤ 2) and failures (|dZ| ≥ 3) are reported separately; the cut-pass fraction is an efficiency. v3 thresholds: core bias shift < 0.05 Z, failure change < 1 percentage point (a draft 0.5 was about one standard error and a reseed reached it), per-Z chi2 p > 0.01, the first two also within 2 standard errors. Self-check on sampled angles: `base2` is free.
- **Report and log split (user).** The numbered decision log moved out of the report into this file; the report holds only the current method and results.
- **22:20, 90° self-check and timing.** `base2` against `base` at 90°: core shift −0.007 ± 0.007, failure change −0.0017 ± 0.0022, p(Z) = 0.61: free. Measured job walls (`.time` files): `base` 1223/1396/1604 s (min/median/max), `step05` 2247/2378/2657 s, so 0.5 mm costs 1.7× (not 2×): about 70% of the cost scales with the number of charge lines. Coarse steps will save less than assumed (about 0.65× at 2 mm, 0.42× at 6 mm). Revised timeline: Phase A about 02:30, Phase B about 05:40, E2 about 06:20, E3 about 07:20.

## 2026-10-19

- **Waiters never fired.** The `step05` and `base` waiters looped on `grep -c`, which exits 1 at a count of 0, so ssh reported failure and the loops never ended; Phase A and Phase B finished unseen (both done before 05:00, far ahead of the 02:30/05:40 estimates, which were already pessimistic). Later waiters append `|| true`.
- **05:06, E3 submitted.** SRIM data done; `tune_eloss90` (120 jobs) submitted by `chain_e3.sh`.
- **Fixed pattern had the wrong radial distribution.** `fix*` gave negative core bias, 10–20% failures and twice the core width, worse with more points. `throwRandomAndGetPadAfterDiffusion` draws r ~ Gaus(0, σ) and a uniform angle (radius half-normal, ⟨r²⟩ = σ²); the pattern used a 2D normal with σ per axis (Rayleigh radii, ⟨r²⟩ = 2σ²), √2 wider and a different shape, a mismatch with the data, which were digitized by the random sampler. Fewer points truncated the wide tail, which is why `fix10` looked best. Fix: half-normal quantile radii, √2·erfinv((i + ½)/N); unit test now checks ⟨r²⟩ = 1, ⟨r⟩ = √(2/π) and the median 0.6745 (the old test checked the 2D-normal moments the bug had). Reruns as `pat300/100/30/10` in `tune_fid90.ini`; `fix*` sections removed from the study file, their outputs left on disk, kept out of the report.
- **Question for the user (not acted on).** The existing sampler's diffusion is not an isotropic 2D Gaussian: per axis its spread is σ/√2. Whether `GetTransverseDiffusion()` is meant per axis or radial decides whether the sampler or the σ is off. The study is self-consistent either way (data and fit share the sampler).
- **Phase A read.** The 1 mm step is not the source of the +0.40 core bias: 0.5 mm moves it by −0.037 ± 0.007 (and lowers failures 0.75 ± 0.24 pp), so 0.5 mm is an improvement, not a neutral setting. Neutral: `step2`, `zs2`, `gain0`. `pts300` is just past the line (+0.022 ± 0.008, 2.9 s.e.).
- **Phase B read.** 100 × 2 is converged (200 × 2, 400 × 2, 100 × 3 neutral). The +0.40 bias is the fit's converged answer: under-searched fits show less core bias only because the prior's pull toward 42 offsets it, with more failures. Rounds beat iterations: 20 × 3 (60 simulations) ≈ 60 × 2 (120). Borderline: `i20r3` at 1.98 s.e. (neutral by the rule), `i200r3` +0.029 ± 0.010 (2.9 s.e., costly by the rule).
